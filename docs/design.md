# 화면·디자인 기준 — 제주 한 바퀴

웹(Next.js)과 앱(Flutter)이 같은 서비스로 보이도록 함께 지키는 기준입니다.

## 벤치마킹한 패턴 (배치와 흐름만 참고, 로고·색·사진·문구는 직접 만든 것만 사용)

- 큰 사진 카드 + 넉넉한 여백, 테마 칩 가로 스크롤, 알약 모양 검색바, 하단 탭 (숙소 예약 앱 계열)
- 상세 화면 순서: 큰 사진 → 제목·한 줄 소개 → 태그 → 소개 글 → 지도 → 행동 버튼 (여행 리뷰 앱 계열)
- 일자별 일정 타임라인 카드 (여행 일정 앱 계열)

## 화면 (웹·앱 공통)

탭 4개: **홈 · 탐색 · AI 플래너 · 내 여행**. 앱은 하단 탭, 웹은 넓은 화면에서 상단 메뉴·좁은 화면(768px 미만)에서 하단 탭.

### 홈
1. 인사 문구 "어디로 한 바퀴 돌까요?" + 알약 검색바(입력 후 확인 → 탐색 화면으로 `q` 전달)
2. 날씨 배너: `/weather` 의 `message` 와 오늘 제주시·서귀포시 날씨. 비 오는 날은 "실내 코스 보기" 버튼(탐색 `indoor=true`)
3. 테마 칩 가로 스크롤(`/meta` 의 themes) → 누르면 탐색 화면 `theme=...`
4. "지금 가기 좋은 곳" 카드 가로 스크롤: 비 오는 날은 `indoor=true`, 아니면 `indoor=false` 로 `/spots` 8개
5. "AI에게 일정 맡기기" 안내 카드 → AI 플래너

### 탐색
- 위: 검색바, 테마 칩, 필터(지역 · 분류 · 실내/실외)
- 본문: 카드 그리드(웹 2~4열, 앱 1~2열) ↔ 지도 보기 전환. 지도는 OpenStreetMap, 핀을 누르면 이름과 "자세히" 링크
- 20개씩 "더 보기"
- 결과가 없을 때·불러오기 실패했을 때의 안내 문구

### 상세
큰 사진(또는 대체 그림) → 사진 출처(작은 회색 글자 "사진: 저작자 · 라이선스", 원본 링크) → 분류·지역 → 제목 → 한 줄 소개 → 태그 칩 → 실내/실외 표시 → 소개 글 → 주소 → 작은 지도 → 버튼 2개: **찜하기**(하트, 로그인 필요) · **이 장소로 일정 짜기**(AI 플래너로 이동, 입력창에 "○○을 포함한 일정" 미리 채움)

### AI 플래너
- 입력: 하고 싶은 여행(글), 며칠(1·2·3 선택), 누구와(혼자·친구·연인·아이와·부모님 칩), 시작 날짜(선택)
- "일정 짜기" → 불러오는 동안 진행 표시 → 결과: 설명 글 + 일자별 타임라인 카드(시간대 · 장소 이름 · 이유, 장소를 누르면 상세)
- `mode` 가 `rule` 이면 "간단 추천" 표시
- "내 여행에 저장"(로그인 필요, 제목 입력)

### 내 여행
- 로그인 전: 설명 + "구글로 로그인" 버튼
- 로그인 후: 사용자 이메일·로그아웃, 탭 2개 — 찜한 곳(카드, 찜 해제) · 저장한 일정(제목·날짜, 펼쳐 보기, 삭제)

## 로그인 동작

- 로그인은 화면이 Supabase Auth(구글)로 직접 하고, 받은 액세스 토큰을 API 요청의 `Authorization: Bearer` 헤더에 넣습니다.
- Supabase 설정 값이 비어 있으면(수업 초반) 앱이 죽지 않고, 로그인 버튼 자리에 "로그인 설정이 아직 없어요" 안내를 보여 줍니다.
- 로그인이 필요한 버튼(찜·저장)을 로그인 전에 누르면 로그인 안내를 띄웁니다.
