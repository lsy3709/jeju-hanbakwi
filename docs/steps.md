# 일차별 브랜치 안내

`main` 은 최종 완성본이고, `step-N` 은 **N일차 수업이 끝났을 때**의 상태입니다.
전날 다 못 끝냈어도, 다음 날 아침 해당 브랜치에서 다시 출발하면 같은 지점에서 수업을 따라갈 수 있습니다.

| 브랜치 | 그날 수업 | 그날까지 있는 것 |
|---|---|---|
| `step-1` | 1일차 · 환경과 첫 배포 | 웹: Next.js 첫 화면 한 장 |
| `step-2` | 2일차 · 화면과 DB | 웹: 디자인 토큰이 입혀진 홈·탐색·상세(임시 데이터 12건) / DB 테이블 SQL / 서버: `/health` · `/meta` · `/spots` · `/spots/{id}` |
| `step-3` | 3일차 · 외부 데이터를 내 것으로 | 서버: 데이터 가공·적재 도구, 검색·필터, 날씨, 사진 제공 / 웹: 서버에 연결(검색·필터·지도·날씨 배너), 3D 지도(MapLibre 지형 + 블렌더 모델) |
| `step-4` | 4일차 · 구글 로그인과 내 데이터 | 서버: 로그인 확인, 찜 / 웹: 구글 로그인, 찜하기, 내 여행(찜한 곳) |
| `step-5` | 5일차 · AI Agent와 앱 시작 | 서버: AI 일정, 일정 저장 / 웹: AI 플래너, 저장한 일정 / 앱: 홈·탐색·상세 |
| `step-6` | 6일차 오전 · 앱 완성 | 앱: 구글 로그인, 찜, AI 플래너, 내 여행 — `main` 과 같음 |

각 브랜치의 `README.md` 맨 위에 "오늘까지 만든 것 / 다음 날 만드는 것"이 적혀 있습니다.

## 쓰는 방법

### 처음 받을 때 (1일차)

GitHub 에서 이 저장소를 **Fork** 한 뒤 내 PC 로 받습니다. 폴더는 `C:\work` 처럼 영문 경로에 둡니다.

```bash
git clone https://github.com/<내 계정>/jeju-hanbakwi.git
```

### 전날 것을 못 끝냈을 때 — 그날 브랜치에서 다시 시작

내가 만들던 것은 그대로 두고, 강사 저장소의 브랜치를 새 이름으로 받아 거기서 이어 갑니다.

```bash
git remote add teacher https://github.com/lsy3709/jeju-hanbakwi.git
```

```bash
git fetch teacher
```

```bash
git switch -c day4 teacher/step-3
```

위 예시는 "3일차까지 끝난 상태에서 4일차를 시작"하는 경우입니다. 브랜치를 바꾼 뒤에는 의존성을 다시 맞춥니다.

| 폴더 | 명령 |
|---|---|
| `web/` | `npm install` |
| `api/` | `pip install -r requirements-dev.txt` |
| `app/` | `flutter pub get` |

`.env`, `.env.local`, `env.json` 은 git 에 올라가지 않으므로 브랜치를 바꿔도 내 PC 에 그대로 남아 있습니다.

### 완성본과 비교해 보고 싶을 때

```bash
git diff teacher/step-3 teacher/step-4 --stat
```

두 브랜치 사이에 어떤 파일이 생기고 바뀌었는지 볼 수 있습니다. 그날 무엇을 만드는지 미리 훑어볼 때도 씁니다.

## 만든 방법 (강사용)

완성본에서 **거꾸로 덜어 내어** 만들었습니다. `step-6` = `main`, `step-5` 는 `step-6` 에서 앱의 로그인·찜·AI 플래너를 덜어 낸 것, … `step-1` 은 `step-2` 에서 첫 화면만 남긴 것입니다.

- 각 브랜치는 그 상태로 검사(서버 `pytest`, 웹 lint·타입·테스트·빌드, 앱 analyze·테스트)가 통과합니다.
- 코드는 완성본의 것을 그대로 쓰고, 덜어 내는 데 필요한 최소 수정만 했습니다.
- `step-2` 의 웹은 서버 대신 임시 데이터(`web/src/lib/sample-spots.json`)로 동작하고, DB 에는 `supabase/seed_step2.sql` 로 12건을 넣습니다.
- `docs/` 의 명세(`api.md`, `design.md`)는 모든 브랜치에서 완성본의 목표를 그대로 적어 둔 것입니다. 그날 브랜치에 아직 없는 주소·화면이 적혀 있을 수 있습니다.

`main` 을 고친 뒤에는 브랜치를 다시 만들어야 합니다(고친 내용이 해당되는 가장 이른 브랜치부터).
