# 코드 분석 기록 — 2026-11-20

리팩토링 · 메모리 · 비동기(성능) 관점에서 전체 코드를 분석한 기록입니다.
같은 지적이 다시 올라오지 않도록, 고친 것뿐 아니라 **고치지 않기로 한 것과 그 이유**도 남깁니다.

## 어떻게 했나

1. **탐색 3축** — 메모리·자원 / 성능·비동기 / 리팩토링·정확성. 읽기 전용으로 후보를 모음 → 20건
2. **반박 검증 2렌즈** — 재현(임시 테스트 20건과 라이브러리 소스로 사실인지 확인) / 영향·대안(이 규모에서 고칠 가치가 있는지, 더 싼 방법은 없는지)
3. **3표 합산** — 코디네이터 + 두 렌즈 중 2표 이상이 모인 것만 확정. 갈린 것은 범위를 줄여 적용
4. **적용** — 테스트를 먼저 추가해 실패를 확인한 뒤 수정, 켜져 있는 서버로 실측

규모 기준: 수강생 1명이 자기 PC·자기 배포본을 혼자 씀, 관광지 68~600건.

## 실측 메모

- Windows 에서 `httpx.Client()` 를 만드는 데만 177~227ms(인증서 묶음 읽기). 리눅스 배포 환경에서는 더 작을 것으로 보지만 측정하지 않음.
- AI 제한 시간은 **요청 1건마다** 적용됩니다. 도구를 여러 번 부르면 전체는 더 길어질 수 있습니다(도구 왕복은 최대 6번).
- 이미지 메모리: 사진 55장을 원본으로 모두 디코딩하면 약 131MB, 한 장 평균 2.4MB. 목록은 보이는 것만 만들므로 3~4쪽 이상 내려 본 뒤 되돌릴 때 다시 받습니다.
